# 0.3.0 — 2026-09-24

## Added

- **`ia_search_items` past-the-end notice** — an empty page beyond the last result names the last page instead of suggesting broader search terms.

## Changed

- **Blank required strings are rejected at the schema** ([#23](https://github.com/cyanheads/internet-archive-mcp-server/issues/23)) — an empty or whitespace-only `query`, `identifier` (`ia_get_item`, `ia_get_text`), or `url` (`ia_get_snapshot`, `ia_find_snapshots`) now fails with `-32602` `invalid_arguments` before any upstream request, where it previously returned a result or the undeclared `empty_query`. Surrounding whitespace is trimmed; the schemas advertise `minLength: 1`.
- **`ia_search_items` `mediatype` is normalized** ([#20](https://github.com/cyanheads/internet-archive-mcp-server/issues/20)) — case-insensitive over the ten media types (`etree` included), with `text`/`book`/`books` → `texts`, `movie`/`video`/`videos` → `movies`, `images` → `image`, `collections` → `collection`. Any other value now fails with `invalid_mediatype` (`-32602`) listing the accepted values, where it previously returned zero results; a zero-result notice names the mediatype applied.
- **`ia_find_snapshots` closest mode without a `timestamp`** ([#11](https://github.com/cyanheads/internet-archive-mcp-server/issues/11)) — now fails as `missing_timestamp` (`-32602`) with a hint naming the format, instead of `no_snapshot_available`.
- **`ia_get_snapshot` `content_fetch_failed`** also covers a failed closest-capture lookup, keeping the lookup's own wait or history-mode hint.
- **README** and `docs/design.md` describe the new extraction, charset, read-limit, fallback, and error behavior.

## Fixed

- **`ia_get_snapshot` text extraction** ([#8](https://github.com/cyanheads/internet-archive-mcp-server/issues/8)) — character references (numeric and named, case-sensitive) decode exactly once, so `&amp;lt;` yields `&lt;`; script and style bodies closed by `</script >`-style end tags, comments, and attribute text no longer reach `text`. The `text` description no longer claims navigation is stripped.
- **`ia_get_snapshot` charset** ([#25](https://github.com/cyanheads/internet-archive-mcp-server/issues/25)) — the page is decoded with its declared charset (BOM, `Content-Type`, `<meta>`), else as UTF-8 when valid, else with Wayback's `x-archive-guessed-charset` or windows-1252; ISO-8859-1 pages no longer return U+FFFD.
- **`ia_get_snapshot` reports the capture Wayback served** ([#19](https://github.com/cyanheads/internet-archive-mcp-server/issues/19)) — `replay_url`, `resolved_timestamp`, and `resolved_status` follow Wayback's redirect instead of echoing the request (`resolved_status` is no longer assumed `200` for exact timestamps). Replay URLs from both Wayback tools are always `https://web.archive.org/…`.
- **Closest lookups fall back to CDX** ([#27](https://github.com/cyanheads/internet-archive-mcp-server/issues/27)) — when the Availability API answers with no capture, one CDX `sort=closest` query (25 s deadline, preferring a `200` capture) runs before `no_snapshot_available` is reported; a fallback that does not complete is `cdx_unavailable`.
- **Upstream failures carry declared reasons** ([#26](https://github.com/cyanheads/internet-archive-mcp-server/issues/26)) — CDX 5xx after retries is `cdx_unavailable`, and an Availability API 5xx, HTML page, or unparseable body is the new `availability_unavailable` (`ia_find_snapshots`) or `content_fetch_failed` (`ia_get_snapshot`), each with a recovery hint. A 429 from any Wayback endpoint is no longer retried: one request, then a hint to wait (the `Retry-After` value when sent).

## Security

- **Linear-time snapshot text extraction** ([#8](https://github.com/cyanheads/internet-archive-mcp-server/issues/8)) — the regex stripping ran in quadratic time on crafted markup (40,000 repetitions of an unclosed `<script>` took over 20 s on Node); a single index scan replaces it and stays linear on any input.
- **Replay body read limit** ([#28](https://github.com/cyanheads/internet-archive-mcp-server/issues/28)) — `ia_get_snapshot` read the whole replay body into memory; it now streams the body and stops at 4 MiB, cancelling the upstream read, with a `notice` when the text comes from a cut page.
