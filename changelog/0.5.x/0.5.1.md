# 0.5.1 — 2026-11-12

## Added

- **`ia_find_snapshots` / `ia_get_snapshot` timestamps**: `timestamp`, `from`, and `to` accept an ISO 8601 date or UTC date-time beside 1–14 digits. A blank `ia_get_snapshot` `timestamp` reads the latest capture. A value that is not one of these forms, or names a date that does not exist, fails as `invalid_timestamp` before any request ([#48](https://github.com/cyanheads/internet-archive-mcp-server/issues/48)).
- **Item URLs as identifiers**: `ia_get_item` and `ia_get_text` `identifier` accept archive.org `details`, `download`, `stream`, `metadata`, `embed`, and storage-node URLs (a `download` or `stream` URL's file is read as `file`); `ia_search_items` `collection` accepts a `details` URL. Any other value holding `/` or `:` fails as `invalid_identifier` ([#52](https://github.com/cyanheads/internet-archive-mcp-server/issues/52)).
- **`ia_get_item` / `ia://item` catalog fields**: `publisher`, `volume`, `isbn`, `oclc_id`, `lccn`, `openlibrary_edition`, `openlibrary_work`, `image_count` (texts only), and `access_restricted`; `files[].private` marks a file the Archive refuses to serve ([#51](https://github.com/cyanheads/internet-archive-mcp-server/issues/51)).

## Changed

- **`ia_find_snapshots` closest mode**: falls back to a CDX closest-capture query when the Availability API answers 429, 408, 425, or 5xx after retries, or sends an unreadable body, within one lookup deadline of the request timeout plus 25 s. A timeout, network error, or 4xx refusal does not fall back ([#53](https://github.com/cyanheads/internet-archive-mcp-server/issues/53)).
- **Framework sync**: framework skills, scripts, and changelog template refreshed; `.env.example` lists `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Fixed

- **`ia_get_snapshot` text paging**: text is returned a page at a time (`char_offset`, `max_chars`, `has_more`, `total_chars`, with a notice naming the next `char_offset` and the `resolved_timestamp` to pass as `timestamp`); it was cut at `IA_MAX_SNAPSHOT_CHARS` without disclosure ([#44](https://github.com/cyanheads/internet-archive-mcp-server/issues/44)).
- **`ia_get_snapshot` non-HTML captures**: plain text, JSON, XML, and JavaScript are read as stored from the `id_` form (line breaks kept, URLs unrewritten) instead of as HTML. A capture that is not text fails as `non_text_capture`; an `id_` refusal after the replay served the capture is `content_fetch_failed`, not "no capture" ([#49](https://github.com/cyanheads/internet-archive-mcp-server/issues/49)).
- **`ia_get_item` list-valued `title` and `date`**: both are string or list, so records such as `00hamigoog` no longer fail output validation ([#46](https://github.com/cyanheads/internet-archive-mcp-server/issues/46)).
- **`ia_get_item` descriptions**: HTML is converted to plain-text lines with links as `label (URL)`; list values with no text are dropped ([#50](https://github.com/cyanheads/internet-archive-mcp-server/issues/50)).
- **`ia_get_text` multi-file items**: `file` selects any readable text file by the name `ia_get_item` lists; Metadata sidecar `.txt` files are never read as the item's text; a multi-file item adds a notice with the count; an unknown or unreadable `file` fails as `invalid_file`; a continuation finds its file by name ([#45](https://github.com/cyanheads/internet-archive-mcp-server/issues/45)).
- **`ia_search_items` filters**: `creator` matches name order and middle names; `language` matches every code and English name of a language; a filter with no letter or digit fails as `invalid_filter`; a `"` in a filter value works; the query is parenthesized when filtered so `OR` binds inside it; an empty-result notice names every filter applied ([#47](https://github.com/cyanheads/internet-archive-mcp-server/issues/47)).
- **`ia_search_items` trailing backslash**: a `query` ending in a backslash that escapes nothing fails as `invalid_query` before any request; filtered, it reached Advanced Search as a backend error.
