# 0.1.2 — 2026-06-06

## Fixed

- **`ia_find_snapshots` closest mode** — SSRF guard now accepts `http://web.archive.org/` in addition to `https://`; the Wayback Availability API returns HTTP URLs, not HTTPS, so the prior guard always tripped the `no_snapshot_available` path. Also unblocks `ia_get_snapshot` when the resolved URL carries an imprecise timestamp. ([#1](https://github.com/cyanheads/internet-archive-mcp-server/issues/1))
- **`ia_get_item` dark items** — `getItem()` now raises `item_not_found` when `is_dark === true` instead of returning empty metadata. Covers `ia_get_item`, `ia_get_text`, and the `ia://item/{identifier}` resource, all of which share the same code path. ([#2](https://github.com/cyanheads/internet-archive-mcp-server/issues/2))
- **`ia_get_snapshot` exact-timestamp 404** — a `NotFound` from `fetchContent()` on the exact-timestamp direct path is now remapped to `ctx.fail('no_snapshot_available', …)` so `data.reason` and the recovery hint surface correctly. ([#5](https://github.com/cyanheads/internet-archive-mcp-server/issues/5))
- **`ia_get_snapshot` `resolved_status` description** — clarified that the field is returned by the Availability API for imprecise timestamps and is assumed 200 for exact 14-digit timestamps (which take the direct path and skip the Availability API). ([#3](https://github.com/cyanheads/internet-archive-mcp-server/issues/3))

## Changed

- **`@types/node`** `^25.9.1` → `^25.9.2`
- **`devcheck.config.json`** — `@cyanheads/mcp-ts-core` added to the outdated allowlist (held at `^0.9.21`)
