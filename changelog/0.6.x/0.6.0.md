# 0.6.0 — 2026-11-17

## Changed

- **Capture URL as `url`** (breaking): `ia_get_snapshot` and `ia_find_snapshots` always read a Wayback capture URL as the page it archives. A capture-URL key that Wayback holds captures of is no longer looked up literally, and a `timestamp` beside it that differs from the URL's own fails as `ambiguous_timestamp` ([#59](https://github.com/cyanheads/internet-archive-mcp-server/issues/59)).
- **`ia_find_snapshots` closest mode**: an omitted or blank `timestamp` reads the latest capture, as `ia_get_snapshot` does; `missing_timestamp` is removed ([#60](https://github.com/cyanheads/internet-archive-mcp-server/issues/60)).
- **One call deadline**: every tool call and `ia://item/{identifier}` read ends within 55 s, or within `IA_REQUEST_TIMEOUT_MS` when that is longer, retries and backoff included. A call that only succeeded past it now fails under its tool's declared unavailable reason, naming the deadline. An `ia_find_snapshots` history expiry is now `cdx_unavailable`, not a bare timeout ([#55](https://github.com/cyanheads/internet-archive-mcp-server/issues/55)).
- **`ambiguous_timestamp`**: new error reason on `ia_get_snapshot` and `ia_find_snapshots`.

## Fixed

- **Capture URLs**: a capture URL passed as `url` is read as its original page, and an impossible embedded timestamp fails as `invalid_timestamp` with `field: "url"` ([#59](https://github.com/cyanheads/internet-archive-mcp-server/issues/59)).
- **List-valued fields in `content[]`**: `ia_get_item` and `ia_search_items` render a field of two or more values as one list item per value, so a value holding a comma or a line break keeps its boundaries ([#57](https://github.com/cyanheads/internet-archive-mcp-server/issues/57)).
- **Availability API errors**: an HTTP 200 carrying an in-body `error` is treated as a failed answer and falls back to CDX; a double failure reports `availability_unavailable`.
- **Wayback URLs as item identifiers**: `wayback.archive.org` URLs passed to the item tools get the `ia_get_snapshot` hint.
- **Exhausted-retry errors**: no longer carry an internal `operation` label in `error.data`.
- **Failed latest-capture lookup**: the hint no longer points at a year that may list nothing.
- **`ia_get_item` / `ia_search_items` formatting**: no longer throws `RangeError` on Node for a field with ~120k or more values.
