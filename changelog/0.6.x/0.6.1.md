# 0.6.1 — 2026-11-21

## Changed

- **Archived-redirect `notice`**: `ia_get_snapshot` names each archived redirect it passed through (a capture of the site's own 3xx) by capture timestamp, HTTP status, and target, whether the capture requested is one or Wayback first redirected the timestamp to a nearest capture that is one ([#63](https://github.com/cyanheads/internet-archive-mcp-server/issues/63)).
- **Next-page `notice`**: after an archived redirect it names the original URL of the capture served; when that URL is itself a Wayback capture URL it names `replay_url` ([#63](https://github.com/cyanheads/internet-archive-mcp-server/issues/63)).
- **`replay_url`** is always on `https://web.archive.org` and carries no `#fragment` on either runtime; a capture reached through the `wayback.archive.org` alias is reported on `web.archive.org`.
- **Closest-capture lookup** uses an answer whose URL is on the `wayback.archive.org` alias.
- **`non_text_capture`** message names an archived redirect that led to the capture.
- **Definition descriptions**: `ia_get_snapshot`'s description, `char_offset`, `has_more`, `replay_url`, `notice`, and the `no_snapshot_available` and `content_fetch_failed` conditions describe the redirect handling.

## Fixed

- **Replay redirects**: the service follows them, up to 10 and on Wayback Machine hosts only, instead of leaving them to the runtime's `fetch`, so Bun and Node reach the same capture. Under Bun, a capture whose archived redirect carried a root-relative `Location` failed as `content_fetch_failed` ([#63](https://github.com/cyanheads/internet-archive-mcp-server/issues/63)).
- **Redirects that reach no readable capture** are `no_snapshot_available`, after one attempt, naming any archived redirect and how the redirects ended: a target never archived, an archived error page, a refusal at the target, a loop, an eleventh redirect, a missing `Location`, or a `Location` off the Wayback Machine or not http(s). A `Location` off the Wayback Machine is no longer followed and returned as the capture ([#63](https://github.com/cyanheads/internet-archive-mcp-server/issues/63)).
- **`id_` read of a text capture** follows the same redirects; a chain that reaches no readable capture is `content_fetch_failed`.
- **Next-page `notice` for a capture of a Wayback capture URL** names `replay_url`; the call it printed before was rejected as `ambiguous_timestamp`.
